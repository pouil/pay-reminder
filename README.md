# Pay Reminder · 补款提醒

给「先付定金、后补尾款」的小生意用的一人份订单提醒工具。

商家在后台录一笔订单和补款日程 → 生成一个买家链接 → 买家打开后把日程**订阅**到手机自带日历 → 之后商家改日期、加日程，买家日历自动同步。买家不用下载 App、不用注册、不用加微信。

> 典型场景：手冲咖啡礼盒定金 150 元，尾款 350 元 11 月 20 日到期 → 买家订阅后，11 月 18 日（提前 2 天）和 11 月 20 日当天，日历各弹一次提醒。

---

## 功能一览

### 商家端（后台 `/`）

- 口令登录（默认 `8888`，Cookie 保存 30 天，登录后不用反复输）
- 新建订单：买家称呼、商品名、定金金额、定金日期
- 删除订单
- 每笔订单下增删改补款日程：日程名称、金额、**到期日**、**提前几天提醒**、备注
- 一键复制买家链接 / 展示二维码（链接即凭证，token 16 位随机）
- 请求诊断接口，便于排查「买家加不上日历」这类问题

### 买家端（`/t/<token>`）

- 展示订单信息：商品、定金、到期日程列表
- **① 一键订阅**：直接跳系统日历添加（iPhone 最省事）
- **② 复制订阅链接**：手动粘贴到日历里添加（跨平台通用）
- **③ 下载 .ics**：一次性导入，适合不支持订阅的日历
- 微信 / QQ 内打开时自动提示「在浏览器打开」
- 链接缺分享码时红字警告，避免白折腾

### 日历同步机制

- 标准 iCalendar（`.ics`）订阅源，含 `VALARM` 提醒
- 到期日与「提前 N 天」各生成一个事件，双保险
- 事件带 `SEQUENCE` / `LAST-MODIFIED`：商家改了日程，已订阅的客户端会应用变更
- 带 `REFRESH-INTERVAL`：客户端按建议频率刷新（实际受客户端限制）
- 支持 `GET` / `HEAD` / `OPTIONS`，兼容会先用 HEAD 探测的日历客户端

## 使用指南

### 一、商家：录入第一笔订单

1. 打开后台地址，输入口令 `8888` 登录；
2. 「新建订单」填写买家称呼（如「王女士」）、商品（如「手动咖啡磨豆机」）、定金金额与日期；
3. 在该订单卡片下「添加补款日程」：名称（如「尾款」）、金额、到期日、提前几天提醒；
4. 把订单的买家链接发给买家（微信直接发链接即可）。

### 二、买家：把日程订阅进手机日历

**iPhone / iPad（推荐）**

1. 点开商家发的链接 → 点「① 一键订阅（先试这个）」；
2. 弹出窗口里如果地址是 `http://` 开头，**手动改成 `https://`**（只改这 5 个字母），再点「下一步」；
3. 若提示 `Validation failed`，改用：设置 → 日历 → 账户 → 添加账户 → 其他 → **添加已订阅的日历** → 粘贴「② 复制」到的链接（务必 https 开头）→ 存储。

**macOS**：日历 App → 文件 → 新建日历订阅 → 粘贴链接。

**Android + Google 日历**：手机 App 本身没有订阅入口。用电脑打开 calendar.google.com → 左下「其他日历」旁的 + → 通过网址 → 粘贴链接；手机登录同一账号后自动同步。

**三星 / 部分品牌自带日历**：不支持「按网址订阅」，只能导入 `.ics` 文件（一次性，不自动更新）。变通办法是走上面的 Google 日历网页版订阅，再在三星日历里勾选显示该 Google 账户的日历。

**微信 / QQ / 支付宝里打开**：先点右上「⋯ → 在浏览器打开」，再进行上面的操作。

### 三、商家：改日程

后台点日程旁的「改」→ 改日期/金额/提醒天数 → 保存。买家已订阅的日历会在下次刷新时同步（iOS 可设 15 分钟~每小时，Google 约 12–24 小时）。**如果买家当初是「下载 .ics 导入」的，则永远不会更新**，这时需要让 ta 重新下载或改用订阅。

## 常见问题

**Q：买家说「日历里加不进去，提示 Validation failed」？**
九成是链接是 `http://` 开头。托管网关会把 http 302 跳到 https，而 iOS 的订阅校验不跟随跳转，直接判失败。让买家把地址改成 `https://` 再试；仍不行就走「设置 → 日历 → 添加已订阅的日历」手动粘贴。

**Q：买家说打开是「链接不完整」？**
链接少了结尾的分享码（托管平台的访问凭证）。把商家发的那条**完整链接**原样转发，不要手工重打。

**Q：改完日程，买家那边没变？**
订阅刷新有延迟（几小时到一天）；另外若买家是「下载 .ics 一次性导入」的，永远不会变。

**Q：三星手机能用吗？**
三星自带日历不支持网址订阅，见上文「三星」一节。

**Q：提醒时间能精确到点吗？**
目前是**全天事件**（按日期提醒），提醒时刻由各日历客户端的默认通知时间决定，例如 iOS 默认当天上午 9 点。

## 技术实现

- **零依赖**：纯 Node.js `http` + `fs` + `crypto`，单文件 `server.js`，数据存 `data.json`
- 后台页、买家页的 HTML/CSS/JS 全部内嵌在 `server.js`（无构建步骤、无前端框架）
- 鉴权：后台用 `admin=1` HttpOnly Cookie；买家页用不可猜的 `token`
- 监听 `process.env.PORT`，绑定 `0.0.0.0`，可直接部署到任意 Node 托管

### 快速开始

```bash
npm start                 # 默认 http://0.0.0.0:3000
cp data.example.json data.json   # 可选：带示例数据
```

### 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` `/admin` | 商家后台（口令登录） |
| POST | `/api/login` | `{pin}` → 设置 admin Cookie |
| GET/POST | `/api/orders` | 订单列表 / 新建 |
| DELETE | `/api/orders/:id` | 删除订单 |
| POST | `/api/orders/:id/reminders` | 新增日程 |
| PUT/DELETE | `/api/orders/:id/reminders/:rid` | 修改 / 删除日程 |
| GET | `/t/:token` | 买家页 |
| GET | `/api/public/order/:token` | 买家页读取的订单 JSON |
| GET | `/ics/:token.ics` | 日历订阅源（GET/HEAD/OPTIONS） |
| GET | `/api/debug/log?key=…` | 最近请求诊断 |

### 部署注意

- 必须监听 `PORT` 并绑定 `0.0.0.0`。
- 若托管平台要求分享码（如 `?sharecode=…`），**订阅源链接本身必须带分享码**——iOS 日历客户端与 Safari 不共享 Cookie。
- 网关若强制 http→https 跳转，iOS 订阅会失败，务必给 https 链接。
- 重新发布前先备份线上 `data.json`，否则会被本地数据覆盖。

## 日历兼容性

| 系统 / App | 按网址订阅 | 入口 |
|---|---|---|
| iOS / iPadOS 15+ | ✅ | 设置 → 日历 → 账户 → 添加账户 → 其他 → 添加已订阅的日历 |
| macOS 日历 | ✅ | 文件 → 新建日历订阅 |
| Google 日历（网页版） | ✅ | 其他日历 + → 通过网址 |
| Outlook | ✅ | 添加日历 → 从 Web 订阅 |
| 小米 / 华为 / OPPO / vivo | ⚠️ 机型相关 | 日历设置 → 订阅日历 / 日历账户 |
| 三星自带日历 | ❌ | 只能导入 .ics；建议改用 Google 日历订阅 |
| 微信 / QQ / 支付宝内置浏览器 | ❌ | 需「在浏览器打开」 |

## 安全说明

- 买家链接中的 token 即访问凭证，不要公开传播或截图外发。
- 后台口令 `8888` 仅用于演示，实际使用请修改 `server.js` 顶部的 `ADMIN_PIN`。
- `data.json` 含真实买家信息，已加入 `.gitignore`，切勿提交到公开仓库。
